# 설명형 Home을 실제 경기 진입 화면으로 연결

대상은 `sungmpar/ft_transcendence_project`, 공개 기준은 `main`의 `2f11bee69c2d55ed938b53f9750119a890396fb7`이다. 아래 내용은 이번 미커밋 후속 변경의 근거이며 배포·사용자 지표를 주장하지 않는다. 단계 D/E의 최종 상태는 [구현 보고서](IMPLEMENTATION_REPORT.md)와 [검증 기록](TEST_REPORT.md)이 우선한다.

## 문제와 제품 판단

실제 실행한 기존 Home 본문에는 안내 카드 9개가 있었고 로컬/AI로 바로 가는 CTA는 각각 0개였다. 사이드바에는 이미 공개 플레이 링크가 있었으므로 “기능에 접근할 수 없었다”고 표현하지 않는다. 새 Home은 로컬 2인·AI·온라인 로비를 같은 규격으로 선택하게 하고, 온라인만 필요한 로그인·상대 찾기 조건을 구분한다. Classic/Power는 경기 규칙이며 local/AI/online은 대전 방식이라는 차이를 문구와 설정 위치에 반영했다.

Home과 공개 허브는 작은 `LaunchPanel`을 공유한다. 공개 화면을 로그인 사용자 API에 묶지 않고 저장된 규칙·난이도·키와 실제 경기 경로만 연결했다. 기술 설명은 접어서 필요할 때 읽게 했다. 네 viewport에서 캡처했고, 데스크톱 첫 화면의 세 CTA와 모바일 계정 메뉴를 실제 클릭·키보드로 검증했다. 스크린샷과 실행 결과는 [검토 패킷](REVIEW_PACKET.md)의 전후 표에서 비교할 수 있다.

## 상태와 수명을 명시한 온라인 복구

플레이어 복귀는 단순히 socket이 다시 연결됐다는 사실로 끝나지 않았다. 서버의 유예가 끝난 경기, 아직 저장 중인 결과, 새 경기와 옛 요청을 구분해야 했다. 요청 ID·경기 ID·인증된 참가 권한으로 상태를 조회하고, 저장 중/실패/복원 불가를 승패와 분리했다. 이미 확인된 0:0 기권 결과를 보기 좋게 6:0으로 바꾸지 않았다.

관전자의 자신의 단절도 별도로 재현했다. 플레이어들이 연결된 상태에서 관전자만 복귀해도 기존에는 tick이 진행하지 않았다. 재구독은 입력 권한을 주지 않고 전체 상태를 다시 적용하며, 과거 관전 권한이 없는 종료 결과 조회를 거부한다. 실제 네트워크 연결의 관측과 결정적 서비스 시험은 서로 다른 증거로 남겼다.

N3는 서버 runner와 클라이언트 buffer를 직접 결합해 원인을 좁혔다. 긴 서버 지연 뒤 버려진 simulation 시간과 클라이언트의 오래된 최소 offset이 충돌해, 최신 위치는 움직여도 중간 보간은 회복되지 않았다. 수정 전에 “재개 후 300ms 안에 두 새 snapshot 사이의 움직이는 위치를 표시”라는 기준을 고정했다. 실행 인스턴스와 clock epoch를 분리한 뒤 이 조건에서 stall은 155ms, pause/resume은 205ms에 회복했다. 정상 지터마다 offset을 덮어쓰는 방법은 선택하지 않았다. 이 수치는 합성 시계 시험 결과이며 실제 WAN 지연이나 사람의 체감 측정이 아니다.

## 타격 이벤트의 전달과 표시 시점

60Hz simulation의 중간 타격을 20Hz snapshot에서 빠뜨리지 않도록 서버에 120tick·64개 한도의 이력을 두었다. full ready는 이력을 소비하지 않고 과거 재생을 건너뛰는 cursor를 제공한다. 클라이언트는 서버 이벤트 ID와 경기·인스턴스·clock epoch를 검사하고 보간된 presentation tick에 맞춰 효과를 전달한다. 6tick보다 늦은 효과는 건너뛰며 득점·서브·재동기화 경계에서 과거 효과를 정리한다. 마지막 화면은 서버 최종 상태로 snap하되 기권을 가짜 득점음으로 꾸미지 않는다. 전달 누락을 완전히 없앴다는 주장 대신 보관 한도와 생략 정책을 문서화했다.

## 리뷰가 구현을 바꾼 사례

- 200% 캡처에서 카드 내부 control 넘침을 발견했다. 문서 전체 폭 검사만으로 충분하다고 보지 않고 카드 내부 경계 단언을 추가했다.
- 독립 에이전트가 guest 실패 시 공개 플레이 대안 소실과 새 탭의 목적지 소실을 재현했다. 단일 실제 guest 요청·고정 callback·허용된 목적지 전달로 수정하고 실제 JWT/DB/브라우저 8개 시험으로 확인했다.
- N3 독립 검토는 적용하면 안 되는 ready ACK가 복구 타이머를 먼저 취소하는 문제를 찾았다. 정확한 실패 경로를 만든 뒤 부작용 없는 사전 검사로 수정했다.
- 서비스 화면 검토는 모바일 입력 폭0과 버튼 클릭 차단을 드러냈다. 화면이 보인다는 검사와 실제 native 클릭·이미지 검토를 함께 사용했다.
- 중복 탭이 거부된 뒤 자동 복구가 멈춘다는 소스 추론은 실제 wire 관찰로 반증됐다. 실제 문제는 6초 동안 5회 추가 연결과 원인 안내 소실이었다. 기존 탭을 닫으면 원래 코드도 자동 복구한다는 결과를 보존하고, 정확한 거부가 확인된 경우만 반복을 중지하도록 범위를 좁혔다. 세 화면의 명시 재연결은 기존 탭 보호와 서버 소유권을 유지한 실제 브라우저 시험으로 확인했다.

## 기여의 범위

원래 팀은 로그인·2FA·채팅·친구·전적과 서비스 구조를 만들었다. 공통 코어와 로컬/AI/온라인의 이전 개편은 이번 공개 baseline에 이미 포함되어 있다. 이번 성과는 그 위의 Home 진입, 로그인 복귀, 수명 관리, 온라인 복구와 표시 경험 개선이다. 기존 팀과 이전 작업을 이번에 새로 만든 기능으로 세지 않는다.

독립 에이전트 리뷰는 외부 사람의 리뷰가 아니다. 자동 브라우저 키 입력은 물리 키보드 플레이가 아니며, 오디오 adapter 호출 검증은 실제 청취가 아니다. 공개 저장소의 코드 통합, 이번 dirty 구현, 실행한 격리 시험, 미실행 운영 환경을 분리해서 설명한다. 재현용 명령·원시 실패·현재 diff는 검토 패킷에 남긴다.
